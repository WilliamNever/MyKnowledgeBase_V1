‌ActionFilterAttribute 是 ASP.NET MVC 和 ASP.NET Core 中用于在控制器动作（Action）执行前后插入自定义逻辑的特性类‌，常用于日志记录、参数校验、权限验证、性能统计等横切关注点。‌‌

🧩 核心机制

继承该类并重写四个生命周期方法，框架会在对应阶段自动调用：‌‌

  1. ‌OnActionExecuting‌：Action 执行前调用，可做参数校验、权限检查，通过设置 context.Result 直接短路请求。
  2. ‌OnActionExecuted‌：Action 执行后调用，可记录耗时、处理返回值或异常。
  3. ‌OnResultExecuting‌：ActionResult 执行前调用，可修改响应头或替换结果。
  4. ‌OnResultExecuted‌：ActionResult 执行后调用。‌‌

📦 基础用法示例

csharp
public class LogActionFilter : ActionFilterAttribute
{
    public override void OnActionExecuting(ActionExecutingContext context)
    {
        // Action 执行前
        Debug.WriteLine($"Executing: {context.ActionDescriptor.DisplayName}");
    }

    public override void OnActionExecuted(ActionExecutedContext context)
    {
        // Action 执行后
        Debug.WriteLine($"Executed: {context.ActionDescriptor.DisplayName}");
    }
}

使用方式：在控制器或 Action 上打 [LogActionFilter] 标签，或在 Startup.cs 中全局注册 options.Filters.Add<LogActionFilter>();。‌‌

⚠️ 常见踩坑点

  • ‌注册问题‌：直接实现 IActionFilter 接口必须手动注册到 DI 容器，否则静默失效；继承 ActionFilterAttribute 相对省心，但类必须是 public 且需有无参构造函数。
  • ‌构造函数注入‌：不要注入 HttpContext 或 Scoped 生命周期的服务，过滤器实例可能在请求外创建。用 context.HttpContext.RequestServices.GetService<T>() 按需解析。
  • ‌执行顺序‌：Order 属性控制同类型过滤器的执行顺序，未显式设置时默认为 0，后添加的反而先执行；IAuthorizationFilter 永远早于 IActionFilter 执行。
  • ‌读取请求体‌：Request.Body 是单次可读流，被模型绑定或上游中间件读取后无法再次读取。安全做法是读取 context.ActionArguments（已绑定完成的参数值），或先启用 EnableBuffering() 再手动重置流位置。
  • ‌异步读取响应‌：在 OnActionExecuted 中不要用 .Result 同步读取响应内容，会导致死锁，应使用 await。‌‌

🎯 典型应用场景

  • ‌接口鉴权‌：在 OnActionExecuting 中校验 Token 或签名，失败时设置 context.Result 返回 401。
  • ‌参数验证‌：检查 context.ModelState.IsValid，无效时返回 BadRequestObjectResult，避免每个 Action 重复写验证代码。
  • ‌操作日志‌：记录请求参数、响应结果、执行耗时和当前用户。
  • ‌响应处理‌：在 OnResultExecuting 中统一加响应头或替换返回结果。‌‌

注意：过滤器执行时机与 MVC 管道阶段强绑定，资源过滤器的 OnResourceExecuting 在模型绑定前执行，此时 ActionArguments 还是空的；而动作过滤器的 OnActionExecuting 里才能看到绑定后的参数。‌‌

‌ServiceFilter 是 ASP.NET Core 中用来给控制器或 Action 局部应用过滤器的特性，它的核心特点是支持从依赖注入（DI）容器解析过滤器实例。‌ 也就是说，过滤器里的构造函数依赖（比如日志服务、数据库上下文）都能自动注入，不用自己手动 new。‌‌

🔧 基本用法

  1. ‌先写过滤器类‌：继承 ActionFilterAttribute 或实现 IActionFilter 等接口，构造函数里声明需要的依赖。
  2. ‌注册到 DI 容器‌：在 Program.cs 里显式注册，比如 builder.Services.AddScoped<MyFilter>();。
  3. ‌用 [ServiceFilter] 标记‌：在控制器或 Action 上加 [ServiceFilter(typeof(MyFilter))]。‌‌

⚠️ 关键注意点

  • ‌必须注册‌：ServiceFilter 要求目标类型已注册到 DI 容器，否则运行时会报 InvalidOperationException: No service for type 'MyFilter' has been registered.。
  • ‌构造函数参数限制‌：[ServiceFilter] 不支持传非服务参数。想传固定值（比如字符串），改用 [TypeFilter(typeof(MyFilter), Arguments = new object[] { "abc" })]。
  • ‌生命周期跟随注册方式‌：过滤器实例的生命周期由注册方式决定（Scoped/Transient/Singleton）。‌‌

🔍 ServiceFilter vs TypeFilter

两者都能实现过滤器依赖注入，区别在于实例来源：‌‌

  • ‌ServiceFilter‌：从 DI 容器获取实例，‌需要先注册‌，生命周期由注册方式控制。
  • ‌TypeFilter‌：不经过 DI 容器，用 ObjectFactory 直接实例化，‌不需要注册‌，每次创建新实例。

想给过滤器传固定参数时，TypeFilter 更方便；想统一管理生命周期或复用已注册服务时，ServiceFilter 更合适。‌‌

📌 常见坑：全局过滤器注入 HttpContext

全局注册的过滤器默认是 singleton，而 HttpContext 是 scoped 服务，直接构造函数注入会启动报错。正确做法是在 OnActionExecuting 里用 context.HttpContext.RequestServices.GetService<T>() 延迟解析。‌‌
